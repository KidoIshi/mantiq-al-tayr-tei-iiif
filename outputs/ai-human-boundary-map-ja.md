# TEI・IIIF研究におけるAI委任境界マップ

更新日：2026年10月13日

## 1. 基本原則

このプロジェクトで身につける技術は、XMLをすべて手入力する能力ではない。研究工程の全体像を理解し、各作業について次の四点を判断できる能力である。

1. AIへ全面委任できるか。
2. AIに候補を作らせ、人間が検証すべきか。
3. 研究者自身が学術的判断を下す必要があるか。
4. 判断と検証の根拠を第三者へ説明できるか。

AIの利用量を減らすことは目的ではない。機械処理に適した作業は積極的にAIへ委任し、研究者の時間を解釈、根拠評価、方針決定、品質保証へ集中させる。

## 2. 委任レベル

### レベルA：AIへ全面委任できる

明確な規則があり、結果を機械的に検証できる作業。

| 作業 | AIが行うこと | 研究者が把握すべきこと |
|---|---|---|
| XML整形 | インデント、名前空間、ID形式の統一 | XMLの親子構造と属性の意味 |
| 定型TEI変換 | 確定済み対句を`<lg>`・`<l>`へ変換 | 採用した要素と代替案 |
| Manifest解析 | Canvas、画像サービス、権利情報を抽出 | ManifestとCanvasの役割 |
| 識別子生成 | 規則に従って`xml:id`を付与 | IDが安定している必要性 |
| 構文検証 | XML、Relax NG、Schematronを実行 | 三種類の検証範囲の違い |
| 集計 | 対句数、半句数、異読数、リンク数を算出 | 数値が完成度の何を示すか |
| 文書・画面の雛形 | README、表示画面、報告書の初稿 | 記載内容と実装の一致 |

研究者は処理手順を暗記する必要はない。ただし、入力、出力、検証方法、失敗時の影響を説明できる必要がある。

### レベルB：AIが候補を作り、人間が検証する

AIが大幅に時間を短縮できるが、誤認が学術的主張に直結する作業。

| 作業 | AIによる代替 | 人間による確認 |
|---|---|---|
| 写本転写 | 文字列の候補を生成 | 原画像との逐語照合 |
| 行・対句分割 | 韻律や配置から境界を推定 | 写本配置と作品構造から承認 |
| 判読困難箇所 | 複数候補と確信度を提示 | `unclear`・`gap`・読みに関する決定 |
| 正規化 | 原綴に対応する検索形を提案 | 正規化規則と例外を承認 |
| 話者候補 | 文脈から話者を分類 | 語りの構造に基づき確定 |
| 物語階層 | 入れ子構造の案を生成 | 研究上の解釈として採否を決定 |
| 画像領域 | 対応行の`xywh`候補を生成 | 本文と画像領域の一致を目視確認 |
| 翻訳対応 | 対句単位の対応候補を作成 | 意味上の対応単位を承認 |
| 校異候補 | 証人間の文字列差を抽出 | 異読、誤記、表記差を分類 |

このレベルでは「AIが生成した」ことより、「研究者が何を見て承認したか」を記録することが重要である。

### レベルC：研究者が決定し、AIが補助する

複数の妥当な選択肢があり、選択そのものが研究成果になる作業。

- 研究目的と対象範囲。
- 使用する写本・刊本と、その資料間の位置づけ。
- 一写本の忠実な転写にするか、複数証人による校訂にするか。
- 採用本文、lemma、異読の評価。
- 話者、焦点化、物語階層の解釈。
- 正規化の程度と、原綴を保持する範囲。
- 日本語訳の最終表現。
- どの不確実性を公開し、どの主張を保留するか。
- 研究成果として何を新規性と位置づけるか。

AIは選択肢、先行例、利点・欠点、矛盾候補を提示できるが、最終判断の主体にはならない。

### レベルD：研究者が責任を負う

- 研究上の最終承認。
- 引用・著作権・画像利用条件に関する公開判断。
- 他者の研究成果やデータに対する適切なクレジット。
- 公募書類や研究発表での完成度・本人貢献の表現。
- 誤りが判明した場合の訂正方針。

AIは確認を支援できるが、研究者としての説明責任を代替しない。

## 3. 理解すべき範囲と、暗記不要な範囲

### 理解が必要

- データがどの資料から来たか。
- TEI要素がどの研究上の概念を表すか。
- IIIF URIが何を指しているか。
- どの検証が成功し、何を検証していないか。
- AIの誤りがどこに入り得るか。
- 最終判断者が誰か。

### AIに任せてよい

- XML構文やJSON構文の細部の暗記。
- 大量のIDの手動付与。
- 同じ規則による反復タグ付け。
- スキーマ取得、コマンド実行、集計。
- 定型的な画面実装やファイル生成。
- 形式的なエラーの一次修正。

## 4. 標準ワークフロー

各工程を次の順序で進める。

1. **研究者が目的を決める**：何を表現・比較したいか。
2. **AIが選択肢を提示する**：採用案、代替案、規格上の制約。
3. **研究者が方針を承認する**：判断理由を短く記録する。
4. **AIが一括実装する**：XML、JSON、画面、検証規則を生成する。
5. **機械検証を行う**：構文、スキーマ、プロジェクト規則を検査する。
6. **研究者が学術的標本検査を行う**：重要例、不確実箇所、境界例を確認する。
7. **AIが修正・再検証する**：変更履歴と結果を保存する。
8. **研究者が最終状態を説明する**：実装済み、確認済み、未検証を区別する。

## 5. 面接での説明例

> 本プロジェクトでは、定型的なXML生成、識別子付与、Manifest解析、スキーマ検証をAIに委任しています。一方、使用写本の選択、判読困難箇所、異読評価、話者・物語階層、画像と本文の対応確認は研究者が判断します。私はすべてのタグを手作業で入力することではなく、TEI・IIIFのデータモデルを理解し、AIの出力に対して適切な制約と検証方法を設計できることを技術的専門性として位置づけています。

## 6. このプロジェクトにおける成功の判定

次の状態になれば、AIを利用しつつ本人の技術として説明できる。

- AIに任せた処理と本人が判断した事項を区別して記録している。
- 採用したTEI設計を代替案と比較して説明できる。
- 検証成功が「学術的に正しい」ことを自動的に意味しないと理解している。
- 不確実な読みや未確認の画像対応を、完成済みとして表示していない。
- 同じ方法を別資料へ再適用できる手順がある。

# TEI・IIIF技術習得ロードマップ

更新日：2026年10月13日

## 到達目標

完成ファイルを所有するだけでなく、研究工程の全体像とAIへの委任境界を把握し、研究者本人が次の質問に自分の言葉で答えられる状態を目指す。

- なぜ一つの対句を`<lg>`、二つの半句を`<l>`で表すのか。
- 写本の綴りと正規化形をどう区別するのか。
- 判読不能、欠損、追記、訂正をどう記述するのか。
- 写本上の行、TEI本文、IIIF Canvas・画像領域をどう結ぶのか。
- TEI公式スキーマと独自Schematronの違いは何か。
- AIによる転写・変換をどのように検証したのか。
- 一写本の転写と、複数写本による校訂版は何が違うのか。

## 学習方法

AIは実装、反復変換、検証、自動検査を担当する。研究者は各段階で少数の具体例を確認し、符号化方針を選択する。すべてを手入力することではなく、全体像を理解して委任可能性を判断し、設計判断と品質管理を実際に行うことを「技術を身につける」と定義する。詳細は`ai-human-boundary-map-ja.md`に記録する。

## 段階別課題

### 第1課題：現在のTEIを読めるようにする

対象：既存の25対句。

理解する項目：

- `teiHeader`と本文の役割。
- `xml:id`、`@n`、`@type`の違い。
- `<div>`、`<lg>`、`<l>`の階層。
- 出典と編集状態を記録する必要性。

完了条件：任意の一対句について、XMLの各要素を口頭で説明できる。

### 第2課題：写本の外交的転写

対象：IIIFで本文葉を閲覧できる一写本の2〜5対句。

理解する項目：

- 写本の綴りと行分けを保持する考え方。
- `<pb>`、`<lb>`、`<unclear>`、`<gap>`、`<supplied>`の使い分け。
- 筆写者の訂正と現代の編集者による訂正の区別。

完了条件：画像とTEIを見比べ、転写の根拠と不確実性を説明できる。

### 第3課題：正規化層を追加する

対象：第2課題の転写。

理解する項目：

- 外交的転写を保存したまま検索用表記を追加する方法。
- `<choice><orig>…</orig><reg>…</reg></choice>`を使う場合と、別レイヤーにする場合の違い。
- Unicode上のアラビア文字・ペルシア文字の差を無意識に統一しないこと。

完了条件：原綴と正規化形のどちらを表示・検索に使うか説明できる。

### 第4課題：TEIとIIIFを対応させる

対象：転写した写本葉。

理解する項目：

- Manifest、Canvas、Annotation、Image APIの役割。
- 葉全体へのリンクと`xywh`画像領域へのリンクの違い。
- TEIの`@facs`とIIIF Web Annotationの関係。

完了条件：一つの対句から対応画像領域を開き、その対応根拠を説明できる。

### 第5課題：検証規則を自分で決める

対象：プロジェクトSchematron。

理解する項目：

- XML整形式、TEI Relax NG、Schematronの検査範囲。
- 「対句は二半句」「`@facs`は確認済みCanvasだけ」といった研究方針を機械検査にする方法。

完了条件：少なくとも一つの独自規則について、必要性と失敗例を説明できる。

### 第6課題：複数証人の比較

対象：同一箇所を含む第二の写本、または書誌的に特定した校訂刊本。

理解する項目：

- 単なる表記差、転記差、写本異読の区別。
- `<listWit>`、`<app>`、`<lem>`、`<rdg>`の役割。
- 採用本文を決めない並列転写という選択肢。

完了条件：一つの実例について、読みと証人の関係を根拠付きで示せる。

## 2026年10月25日までの現実的な到達点

1. 現在の25対句によるTEI構造・検証の理解。
2. 一写本の2〜5対句について、画像に基づく外交的転写。
3. 少なくとも一つのCanvasまたは画像領域との対応。
4. 研究者が承認した符号化判断の記録。
5. 実装済みと未検証を区別した技術報告・公募用説明。

写本本文を閲覧できるIIIF資料が確保できない場合は、第2〜4課題を無理に完成扱いにしない。その場合でも、資料探索の記録、利用不能理由、設計案、検証可能なTEI基盤を成果として残す。

## AIと研究者の実践的分担

| 作業 | AI | 研究者 |
|---|---:|---:|
| IIIF資料候補の探索とManifest解析 | 主担当 | 候補の学術的妥当性を判断 |
| 写本画像の転写候補作成 | 主担当 | 原画像と照合して承認・訂正 |
| TEIタグ付与と一括変換 | 主担当 | 記述方針を選択 |
| スキーマと検証スクリプト | 主担当 | 規則が研究目的に合うか判断 |
| 話者、物語階層、異読評価 | 補助 | 主担当 |
| IIIF領域候補の生成 | 主担当 | 本文との対応を承認 |
| 技術説明・面接回答の草案 | 主担当 | 自分の言葉に直して説明 |

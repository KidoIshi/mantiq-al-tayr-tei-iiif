# jTEI投稿・v0.3.0準備監査

監査日：2026年11月13日

## 結論

現状は、公開済みの方法論的試作として技術的に堅実であり、jTEI Project/Tool paperの原稿作成へ進める水準にある。ただし、投稿前に「別環境での外部コードレビュー」「Zenodo DOI」「英語論文本文」「AI利用開示の最終承認」が必要である。批判校訂版としてではなく、検証可能な二写本TEI・IIIFワークフローとして提示する。成果の学術的位置づけに関する三点は、2026年11月13日に研究者が承認した。

## 今回確認・修正した事項

### 重要度 High（修正済み）

- 公式TEI Allスキーマの取得先が更新可能な`/release/` URLだった。TEI P5 4.12.0のVault URLへ固定し、SHA-256不一致時は検証を停止するよう変更した。

### 重要度 Medium（修正済み）

- 閲覧画面検査はコード中の必要機能を確認する静的回帰検査であり、現在のブラウザを自動操作する試験ではない。出力中の過去の手動確認記録を`manual_browser_check_record`とし、当該スクリプトが再実行していないことを明記した。
- 公開準備検査が`CITATION.cff`のバージョンを`0.2.0`へ固定していた。記載された版を解析する方式へ変更し、将来のv0.3.0で検査コードを書き換えなくてよいようにした。
- 英語READMEがなかったため、論文査読者・再利用者向けに範囲、再現手順、制限、ライセンスを明示した`README.en.md`を追加した。
- Python依存関係のうち`lxml`だけが範囲指定だったため、監査環境で全検証を通した6.1.3へ固定した。
- DH2027応募草稿とローカルPDF生成補助を、jTEI用ソフトウェア公開物へ誤って混入させないよう`.gitignore`で明示的に除外した。

### 重要度 Low（修正済み）

- 技術報告に「GitHub公開が未実装」という公開前の記述が残っていたため、未完了項目をZenodo DOIへ更新した。
- Persan 348の60 Annotationと全体78 Annotationの説明を分け、件数の読み違いを防いだ。

## 検証結果

- `python -m compileall -q scripts`：合格。
- `python scripts/verify_all.py`：9工程すべて合格。
- `python scripts/check_release_readiness.py`：blocker 0、warning 0。
- `git diff --check`：空白エラーなし。
- 検証対象：39対句、78半句、3 surface/Canvas、3 AnnotationPage、78 Annotation。

これらはXML・スキーマ・プロジェクト規則・ファイル間整合性を保証する。写本の読み、字形判断、領域の学術的妥当性、権利判断、論文の新規性を保証するものではない。

1. 外部AIレビュー依頼文に基づく別環境レビューの整理と、再現できる技術指摘の修正。
2. v0.3.0候補の差分、件数、リンク、メタデータ、GitHub Actions結果の再監査。

### 研究者本人が判断する

1. Persan 348とFSC-MS-28の個別書誌・写本記述の最終文言（成果全体の位置づけ三点は承認済み）。

3. AI利用開示が実際の分担を正確に表し、投稿時点のjTEI規程に適合するか。
4. 外部AIレビュー指摘のうち、写本読解・校訂方針に関わるものの採否。
5. v0.3.0の公開、Zenodo DOI確定、原稿投稿の最終承認。

## 推奨する順序

1. 今回の修正差分を人間が概観する。
2. 外部AI相互レビューを実行し、報告と対象SHAを保存する。
3. 指摘対応後に全検証を再実行し、v0.3.0 Releaseを作る。
4. v0.3.0をZenodoへ保存してDOIを取得する。
5. DOIと確定版の数値・図を用いてjTEI原稿を完成させる。
6. jTEIへ直接投稿し、researchmapには査読状況を正確に区別して登録する。

## 研究者確認済み

2026年11月13日、研究者は英語READMEの「本プロジェクトは批判校訂版ではない」「Persan 348は最良写本・底本として選んだのではない」「研究者が画像照合したが外部査読ではない」という三点が研究上の意図と一致すると承認した。今すぐ写本本文を追加確認する必要はない。今後の写本判断は、外部レビューで具体的な論点が出た場合に限って切り分ける。
